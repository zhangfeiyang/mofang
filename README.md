# Cube AR

离线运行的 Android 三阶魔方扫描与实时还原指引 App。

## 使用

1. 安装 APK，允许相机权限。
2. 在画面任意位置、任意距离展示魔方；App 会主动寻找贴纸轮廓并让 AR 四边形跟随魔方，不需要对准固定框。
3. 自由转动魔方，依次露出六个面（包括顶面和底面）。当某个面的至少 8 个网格位置可检测、9 个色块可解析且连续多帧一致时自动采集。底部圆点显示进度。
4. 六面状态通过物理合法性校验后，App 在本机计算还原步骤。
5. 按 AR 箭头操作。每一步先让提示颜色的中心块面对镜头；App 识别动作完成后自动刷新下一步。

App 按常见配色映射中心块：白 U、红 R、绿 F、黄 D、橙 L、蓝 B。六个面的拍摄旋转方向不受限制，程序会自动寻找合法朝向。纯绕竖轴一圈只能看到四个侧面，无法唯一恢复 54 个色块，因此还必须展示顶面和底面。

## 训练检测模型

```bash
# 1. 合成训练数据（角点标注由投影解析得出，无需人工标注）
python3 tools/synth_cube.py --count 50000 --size 160 --height 288 --workers 7 \
    --out data/train --backgrounds "path/to/backgrounds/*.png"

# 2. 训练并导出 ONNX
python3 tools/train_detector.py --data data/train --epochs 24 --batch 96 --width 1.5 --out models

# 3. 放进 assets
cp models/cubeface.onnx app/src/main/assets/
```

渲染器随机化位姿、光照色温、高光、背景杂物，以及握持魔方的手（掌部 + 跨过棱边的手指 + 接触阴影）。

两个影响很大、但不直观的约束：

- **合成画布比例必须等于部署画面比例。** 用方形训练、竖屏部署会让真实帧检测率从 19/22 掉到 9/22。
- **正面占优阈值（`MIN_FACE_DOMINANCE`）是召回与精度的直接权衡。** 接近 45° 时两个面投影面积相近，
  「最大的面」会在两者之间跳变，几乎相同的画面会带上不同面的角点。设为 1.35（≈36° 倾角）时角点误差
  低至 0.021，但把大量三四分之一视角判成 absent，真机漏检 17%；设为 1.10（≈42°）后漏检降到 4.6%，
  代价是角点误差回到 0.029，且极端倾角下网络会给出跨两个面的错误四边形。
  后者靠把 `PRESENCE_THRESHOLD` 提到 0.85 挡掉——该分数是强双峰分布，从 0.60 提到 0.85 只损失不到 3%
  的检出，却能滤掉网络自己也不确定的那批。

## 实现

- CameraX `Preview` + `ImageAnalysis`，全画面分析并丢弃积压帧。
- **CNN 定位当前朝向面的四个角点**（`CubeFaceModel`，ONNX Runtime + NNAPI，1.3 MB）。编码器-解码器结构，
  角点由 spatial-softmax 热力图的 soft-argmax 得出。整帧按相机自身的竖屏比例送入，不做方形裁剪。
- OpenCV 的轮廓 + RANSAC 网格拟合作为**兜底**：模型加载失败或某帧置信度不足时接管。
- 根据检测结果计算动态四边形，透视矫正后解析九个色块；AR 覆盖层平滑跟随位置、大小和旋转。
- 角点先做多帧平滑再取样（`CornerSmoother`），抖动只减不增；魔方一转就立即跟上，不拖影。
- 稳定性按 **Lab 原始读数**判定而非颜色名称：名称会在红/橙之间跳，读数不会。稳定期内的多帧读数取平均后再送去指派。
- 允许 2 个不可信格子（手指/反光），交给全局指派用约束反推，不再因为一两格丢掉整帧。
- 采样patch取每格 100px 中的 28px 中心区：patch 过宽时四边形差几个百分点就会吃到贴纸黑边，
  实测这一项就占了检出帧的 1/7。
- 稳定判定容忍连续 2 帧掉帧。检测与采样各自偶尔丢帧，若每丢一帧就重新计数，
  实际采集成功率会远低于单帧成功率。
- 短时遮挡只影响采集，不会让跟踪框立即消失。
- 每格取**中位数**而非均值，避开高光和贴纸黑边；格内像素离散度过大（手指遮挡、镜面反光、压到格线）时该格标记为不可信。
- 颜色**不做逐格阈值判定**。每格只记录 CIELAB 原始读数，六面集齐后一次性求解：以六个中心块作为本次扫描的颜色原型，在「每色恰好 9 块」的硬约束下用匈牙利算法做全局最优指派。实拍中红与橙的色相只差 2–4°，固定阈值必然从色块簇中间劈开，而 Lab 下两者相差约 30 个明度单位。
- 面的分组用**相对**规则：两次观测算同一个面，当且仅当距离小于整池色彩跨度的 30%。绝对色差阈值会让某两个面
  永久互撞、扫描卡在 5 面（这是实测踩过的坑）。分组宁可分多也不合并——多分只是多失败一次求解，合错则无法挽回。
- `CubeRules` 用魔方结构剔除误识别：角块连接三个互不相对的面、棱块连接两个，8 个角块和 12 个棱块各自唯一。
  它不只拒绝，还能定位是哪一块错了，装配失败时据此换用该面的次优观测重试。
- 同一个面的多次观测**先按 roll 对齐再逐格取中位数**合成一条读数，而不是挑其中"置信度最高"的一条。
  跨两个面的四边形会读出九个平整色块，置信度反而**高于**被手指挡掉一格的诚实观测；按置信度挑代表
  等于把这个面交给它。池子里出现两个这样的观测，扫描就再也解不出来——每次只换一个面的重试
  仍然信任另一个。中位数直接把它投票投掉。
- 合法性校验失败后的重试顺序：全体共识 → 每个面各丢掉与共识分歧最大的一次观测 → 逐面尝试。
  中间那步是为「一个倾斜视角同时毁掉好几个面」准备的。
- 求解失败不清空观测，回到扫描态继续累积——多看几眼正是消除歧义的办法。失败时会把整池读数写到
  `getExternalFilesDir(null)/scan-fail.json`，可用 `adb pull` 取回离线复现（部分机型屏蔽第三方 logcat）。
- 求解成功后记下这次扫描的六个原型（`ScanPalette`），引导阶段按最近原型给实时画面贴标签，
  不再回退到固定阈值。
- 内置 MIT 许可的 `min2phase` 两阶段求解器，全程离线。
- 求解阶段识别目标中心面及转动后的色块排列，自动推进提示。

相机帧不保存、不上传，也不需要网络权限。
